# Keystroke Dynamics: Random Forest, Logistic Regression, SVM, and XGBoost

Two reproducible files:
- `Keystroke_RF_LR_SVM_XGBoost_Colab.ipynb`: **self-contained Colab notebook** with upload + `pd.read_csv()`, visualizations, and all training/evaluation steps.
- `keystroke_four_models.py`: **standalone version** with a command-line interface and the same four Pipelines + ensemble.

## Run on Google Colab

1. Open [Google Colab](https://colab.research.google.com/) and upload `Keystroke_RF_LR_SVM_XGBoost_Colab.ipynb` (or open it from the private GitHub repository).
2. Run the first **install** cell.
3. Run the **upload CSV** cell and choose your `keystroke_features (1).csv` file. It explicitly calls `df = pd.read_csv(csv_path)` and previews the data.
4. Run the remaining cells in order to perform 75/25 stratified train/test split, train four independent Pipelines, tune using 5-fold CV, and evaluate soft-voting ensemble.
5. Download `keystroke_four_model_results.zip` generated by Step 11.

The notebook requires only the CSV upload; it does not need the standalone Python script.

## Pipeline architecture

| Name | Pipeline steps | Hyperparameters searched |
|---|---|---|
| Random Forest | `SimpleImputer(median)` → `RandomForestClassifier` | Trees, maximum depth, leaf size |
| Logistic Regression | `SimpleImputer(median)` → `StandardScaler` → `LogisticRegression` | Regularization strength and class weights |
| SVM | `SimpleImputer(median)` → `StandardScaler` → RBF `SVC(probability=True)` | C, gamma, class weights |
| XGBoost | `SimpleImputer(median)` → `XGBClassifier` | Trees, depth, learning rate, subsampling |
| Soft Voting | Four **tuned Pipelines** in a `VotingClassifier(voting="soft")` | Equal weights |

Five-fold stratified CV only on training data is used to compare models and select the final Pipeline. Predictions for all five candidates on held-out data are reported, but **the test results are not used to pick the winner**. The candidate CV ranking is exploratory and may be optimistic after tuning hyperparameters. Increasing tuning iterations changes results and is not a guarantee of improvement.

## Verified outputs on supplied keystroke CSV

The supplied dataset has **500 rows, 8 numerical features, 5 classes**. Split: **375 train / 125 test**, `random_state=42`.

| Candidate | Mean 5-fold training CV accuracy | Held-out test accuracy |
|---|---:|---:|
| Random Forest | 21.6% | 18.4% |
| Logistic Regression | 22.7% | 17.6% |
| SVM | **23.7%** | **23.2%** |
| XGBoost | 19.5% | 19.2% |
| Soft Voting (RF + LR + SVM + XGB) | 21.1% | 16.8% |

The **SVM** was selected by training CV and achieved **23.2%** on held-out data, exactly the **23.2% majority-class baseline**. The selected model predicts primarily the largest class (user_004), so 23.2% does **not** indicate genuine user recognition. Accuracy near the ~20% chance level means the given features are not adequate for real keystroke authentication.

Outputs under `outputs/`:
- `keystroke_cv_scores.csv` — training CV table including selected parameter values
- `keystroke_holdout_scores.csv` — holdout accuracy, balanced accuracy, macro-F1
- `keystroke_metrics.json` — selected model and split information
- `keystroke_confusion_matrix.png` — final confusion matrix
- `keystroke_best_pipeline.joblib` — trained selected Pipeline and label encoder (private)
